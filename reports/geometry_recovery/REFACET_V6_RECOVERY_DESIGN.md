# Refacet-v6 recovery design

Status: **design only; no remote launch authorized**.

V5 established that all eight immutable source artifacts, totaling 331,691,833 bytes, were copied to its persistent output in roughly eight minutes. It did not publish a later stage marker, DAGMC H5M, candidate manifest, build seal, terminal return code, or resource record before it was observed terminal after its three-hour boundary. The evidence therefore identifies an observability and staging failure, but it does not identify a specific CadQuery or Gmsh substage as the cause.

V6 separates diagnosis from scientific meshing. A 4-thread, 90-minute import/fragment diagnostic will first stage the exact source packet to a fresh host-local `/dev/shm` root and execute one shared production import, identity mapping, BooleanFragments, fragment matching, and topology routine without meshing or H5M output. Every stage writes a hash-chained, exclusive-create persistent start/completion receipt. Gmsh thread limits are set and read back before import or fragmentation, then again before any later mesh. The diagnostic cannot qualify geometry or trigger a successor.

Each lane has two path roles. A fresh sealed operational root is created before `core-budget` so the required log parent exists. It has an immutable, hash-sealed code/input/control/launcher subtree and a separate writable allowlist for log, PID, time, stage, diagnostic, publication, terminal, and collection evidence; additions elsewhere fail. Separate scratch and scientific publish roots remain wholly absent until the launcher claims them atomically. Diagnostic and coarse runs use separate runtime receipts and validations binding their run mode, threads, immutable source, intended-but-absent staged source, scratch output, publish root, and every helper hash. The scientific run rehashes staged inputs and revalidates runtime before CAD work.

Only after the diagnostic passes and is independently reviewed may a separate 32-thread coarse attempt be prepared. Its six-hour value is a candidate ceiling, not an entitlement: the actual limit must be justified from measured diagnostic stage timings and independently reviewed. It may be reduced; increasing it requires a new review.

The outer Bash launcher will place GNU `time` outside GNU `timeout`, capture the exact return code after `timeout` returns, and atomically publish a terminal receipt before returning the same code. This evidence is independent of scientific Python stdout buffering. Python will additionally run unbuffered and publish hash-chained stage receipts, but stdout will never control acceptance. After the guarded process exits, a separate collector rehashes the log, timing, stage, diagnostic/artifact, publication, and terminal evidence and checks it against the terminal receipt.

Scientific computation occurs in a fresh host-local scratch tree. The launcher proves `/dev/shm` is tmpfs, has at least 64 GiB and 10,000 inodes free, inventories stale same-user scratch use, requires at least 192 GiB host memory before staging, and rechecks at least 128 GiB afterward. Inputs are copied from the frozen packet and rehashed before use. Completed artifacts are published with exclusive, no-symlink copies to the persistent root and rehashed there; the candidate manifest is published next, the build seal last, and an external publication receipt binds the complete transaction. Scratch is preserved after failure until an explicit evidence disposition is recorded.

The diagnostic must publish a create-only report and external receipt binding its complete import/fragment/topology payload and explicit absence of H5M. Gmsh options `General.NumThreads`, `Geometry.OCCParallel`, and `Mesh.MaxNumThreads1D/2D/3D` are frozen; thread controls are read back before import/fragmentation, after sizing calls, and before mesh.

Before any remote action, the implementation and focused tests must pass, the exact code and controls must be hash-frozen, and an independent reviewer must approve both this design and the concrete launch artifacts. Diagnostic runtime preflight, diagnostic execution, coarse runtime preflight, coarse meshing, and coarse qualification are five separate terminal gates with no automatic successor. Refined faceting and OpenMC remain blocked.
